AI EARLY OUTBREAK DETECTION & SOURCE LOCALIZATION SYSTEM
=========================================================

PROJECT OBJECTIVE
-----------------
Build an AI system that:

1. Detects disease outbreaks from historical disease-surveillance data.
2. Identifies the likely geographic origin/source of an outbreak.
3. Tracks the geographic spread/intensity of the outbreak.
4. Generates data for a geographic heat map.
5. Provides the results through a FastAPI backend.
6. Displays the results through a frontend/dashboard.

IMPORTANT:
This project is NOT primarily a disease-risk prediction system.
The main objective is OUTBREAK DETECTION + SOURCE LOCALIZATION + HEAT MAP.


=========================================================

=========================================================
2. DATA PREPROCESSING
=========================================================

Required preprocessing:

- Remove duplicate records.
- Standardize disease names.
- Standardize state names.
- Standardize district names.
- Handle missing values.
- Convert dates into proper datetime format.
- Sort records chronologically.
- Convert data to a consistent weekly representation.
- Validate latitude and longitude.
- Detect impossible/outlier values.
- Check duplicate State + District + Disease + Week combinations.
- Verify that geographic coordinates are valid.

The data must be ordered chronologically because this is a
time-dependent outbreak detection problem.


=========================================================
3. FEATURE ENGINEERING
=========================================================

Create historical disease features for each:

State + District + Disease

Case-history features:

- cases_lag_1
- cases_lag_2
- cases_lag_3
- cases_lag_4

Rolling features:

- rolling_mean_4
- rolling_mean_8
- rolling_std_4
- rolling_std_8

Environmental features:

- temperature
- precipitation
- LAI

Possible environmental lag features:

- temperature_lag_1
- precipitation_lag_1
- LAI_lag_1

Other useful features:

- week_of_year
- month
- seasonal indicators
- recent case growth
- death trends
- geographic coordinates


=========================================================
4. MAIN TASK — OUTBREAK DETECTION
=========================================================

The first ML task is:

"Is an outbreak occurring in this location for this disease?"

This is NOT simply a generic risk prediction task.

The system should identify abnormal disease activity that corresponds
to a genuine historical outbreak.

Potential models:

1. Random Forest
2. XGBoost
3. MLP (Multi-Layer Perceptron)

Random Forest should be used as a strong baseline.

XGBoost can be used as another tabular ML comparison.

MLP can be used as the actual neural-network model.

IMPORTANT:
Random Forest is NOT a neural network.

Random Forest = ensemble of decision trees.
MLP = neural network.


=========================================================
5. OUTBREAK TARGET
=========================================================

Define a reproducible outbreak label.

Example concept:

Historical disease activity
        ↓
Identify sustained/meaningful increase
        ↓
Define outbreak episode
        ↓
Create outbreak label

The outbreak definition must be established independently of
the model predictions.

Do NOT define an outbreak as:

"Whatever the model detects."

That would cause circular evaluation.

The exact outbreak definition should be documented and applied
consistently to the dataset.


=========================================================
6. TIME-BASED TRAINING
=========================================================

Do NOT randomly shuffle the entire dataset for train/test splitting.

Use chronological splitting.

Example:

2009 ───────── 2018 | 2019 ─ 2020 | 2021 ─ 2022
       TRAINING      | VALIDATION  |    TEST

The exact years can be adjusted according to the dataset.

MAIN RULE:

The model must never use future information to predict the past.

Avoid data leakage.

For example:

Week t
  ↓
Only information available up to Week t
  ↓
Predict outbreak at Week t+1 / future horizon


=========================================================
7. MODEL 1 — OUTBREAK DETECTOR
=========================================================

Recommended experiments:

Model A:
Random Forest

Model B:
XGBoost

Model C:
MLP Neural Network

Compare their performance.

Do not assume the neural network will automatically perform better.

Possible output:

{
    "outbreak": true
}

{
    "outbreak_probability": 0.91
}


=========================================================
8. MODEL 2 — SOURCE LOCALIZATION
=========================================================

After an outbreak is detected, the next question is:

"Where did the outbreak most likely originate?"

Do NOT simply assume:

District with highest cases = source.

The location with the most cases could be a secondary amplification
site rather than the original source.

Consider:

- Temporal precedence
- Case growth
- Geographic proximity
- Neighboring-district propagation
- Environmental similarity
- Disease-specific patterns
- Timing of first significant increase
- Spread from one district to surrounding districts


=========================================================
9. SOURCE DETECTION APPROACH
=========================================================

Initially, use a source-ranking approach rather than immediately
building a complicated second neural network.

For every affected district, calculate a source score using factors
such as:

- Temporal precedence
- Case-growth strength
- Spatial relationship
- Propagation pattern
- Environmental similarity

Example output:

1. District A → Source score: 0.87
2. District B → Source score: 0.64
3. District C → Source score: 0.42

The system can then report:

Likely source:
District A

Confidence/source score:
0.87

IMPORTANT:
Call this "likely source" or "source candidate", not a confirmed
epidemiological source unless the available evidence supports that.


=========================================================
10. OUTBREAK SPREAD ANALYSIS
=========================================================

After identifying the outbreak and likely source, analyze how it
spreads geographically.

Example:

Week 1:
District A → first major increase

Week 2:
District B → increase
District C → increase

Week 3:
District D → increase

Possible representation:

District A
   ↓
District B ───→ District D
   ↓
District C

This creates a temporal-spatial outbreak progression.


=========================================================

Generate geographic information for the frontend.

Each district/location can contain:

- Latitude
- Longitude
- Cases
- Outbreak score
- Source score
- Detection date
- Week
- Disease

Example:

{
    "district": "Kannur",
    "latitude": 11.8745,
    "longitude": 75.3704,
    "cases": 142,
    "outbreak_score": 0.91,
    "source_score": 0.72

The frontend can use this information to generate a geographic
heat map.

=========================================================
17. EVALUATION
=========================================================

Evaluate the system on historical outbreaks.

Important metrics:

OUTBREAK DETECTION:
- Precision
- Recall
- F1-score
- Detection lead time
- False alarm rate

SOURCE LOCALIZATION:
- Top-1 source accuracy
- Top-3 source accuracy
- Distance between predicted source and reference source
- Temporal correctness
- Geographic localization error

SPATIAL OUTPUT:
- Correct affected districts
- Geographic spread consistency
- Heat-map correspondence with historical outbreak data


=========================================================
18. HISTORICAL OUTBREAK REPLAY
=========================================================

A particularly important evaluation method:

Take historical data and replay it chronologically.

Example:

Historical outbreak:
Week 10 → initial increase
Week 11 → expansion
Week 12 → major outbreak
Week 13 → peak

Replay the data:

Week 10
  ↓
System processes information available at Week 10

Week 11
  ↓
System updates its detection

Week 12
  ↓
System identifies outbreak

Then compare the system's result with what actually happened.

This helps evaluate whether the system could have detected the outbreak
using information that would genuinely have been available at that time.
